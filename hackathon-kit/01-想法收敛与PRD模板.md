# 黑客松 PRD 模板（写给 AI 的产品说明书）

> 用法：把这份文档填完，再让 WorkBuddy 开始写代码。
> 规律很简单：**你填得越具体，它生成的东西越接近你要的。** 空着的地方就写"暂无"，别留白。
> 这份文档不是给评委看的，是给 AI 看的——所以写"页面显示什么"，别写"要有好的用户体验"。

---

## 0. 一句话说清

模板：**（谁）在（什么场景）遇到（什么麻烦），现在要花（多久/多少钱）解决；我用 AI 帮他（做什么），让他只需（几步）就能（得到什么）。**

示例：
> 小商家每天要花 2 小时手写商品文案；我用 AI 让他上传一张商品图，30 秒拿到 3 条可直接复制发布的文案。

你的：
> ____

**自检：** 如果这句话里把"AI"去掉依然成立，说明 AI 是硬加的，评委一眼看穿。要么换切入点，要么换想法。

---

## 1. 真实痛点

- 谁会遇到这个问题？（越具体越好，**别写"所有人"**）
- 他现在怎么解决？哪一步最难受？
- 你怎么知道这是真痛点？（自己踩过 / 问过几个人 / 有公开数据）

---

## 2. 不做什么（最关键的一节）

写清楚不做什么，能直接防止 AI 生成一堆你用不上的功能，也能帮你守住工期。

- [ ] 不做用户注册登录（除非评委必须体验多用户）
- [ ] 不做支付
- [ ] 不做后台管理
- [ ] 不做多语言
- [ ] 不做：____

---

## 3. 演示路径（决定名次的一节）

评委打开网页后 **30 秒** 内必须看到什么，按秒写：

1. 打开首页 → 看到 ____
2. 点击 ____ → 出现 ____
3. AI 在 ____ 这一步起作用，输出 ____
4. 最终得到 ____ ← **这是"啊哈时刻"，必须存在**

**原则：先定演示路径，再定功能列表。** 功能是为路径服务的，路径之外的功能全部砍掉。

## 5. AI 用在哪

- **输入是什么：**（用户填的文字 / 上传的图片 / 表格数据）
- **交给 AI 做什么：**（总结 / 生成 / 分类 / 提取 / 推荐 / 改写）
- **输出是什么：**（一段文案 / 结构化字段 / 评分 / 标签）
- **兜底方案：AI 调用失败时显示什么？** ← **必填，现场会救命**

兜底方案建议：预置 2–3 组"看起来像真的"的示例结果，网络挂了、超时了、token 超了，直接顶上去，页面照样能讲完。

## 6. 数据与存储

- 需要保存用户数据吗？（**不需要 = 最省事**）
- 需要登录吗？（**不需要 = 最省事**）
- 需要调外部 API 吗？（优先选免密钥的方式，省配置、省钱、省时间）

---

## 7. 视觉风格

- 基调：____（深色科技感 / 浅色清爽 / 纸质 / 其他）
- 底色 / 文字色 / 强调色：____
- 字体感觉：____（硬朗 / 圆润 / 手写）
- 想要的动效：____（入场弹入 / 滑入 / 淡入 / 打字机 / 数字滚动 / 呼吸）
- 参考产品：____（写 1–2 个你觉得好看的产品名）

---

## 8. 技术约束（照抄即可）

- 交付形态：网页，一个能直接在浏览器打开的在线链接
- 优先级：**能演示 > 功能全 > 代码优雅**
- 明确不要：自建服务器、复杂前端框架、Docker、微服务
